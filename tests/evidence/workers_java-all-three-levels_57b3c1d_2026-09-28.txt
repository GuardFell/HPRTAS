What this run does not cover
----------------------------
* Four scenarios have still never been run: TC-02, TC-13, TC-16 and TC-20. TC-13 and TC-20 need
  a signed-in user completing user tasks through Tasklist; TC-16 needs a letter left outstanding
  past seven days so the timer boundary event fires.
* Every user-task variable in these runs was supplied with the task completion call
  (`POST /v2/user-tasks/<key>/completion`), not by a person filling in a rendered form, so task
  claiming, form validation and the candidate-group restriction are not exercised (`DEF-08`).
  The form bindings themselves are proved by `verify_hprtas_engine_forms.py` instead.
* No user is authenticated and candidate groups are not enforced (`DEF-07`), so separation of
  duties rests on the lane structure alone.
* The simulated services keep their ledgers in memory, per worker process (`DEF-10`), so every
  duplicate-prevention result here holds only within one worker process.
* `DEF-12` is not closed entirely by the fix it records: the incident is gone, but no form has a
  field for the offending variable, so a Tasklist user cannot clear card details that have
  reached the process.
* `DEF-14` still has one condition on the only outgoing flow of an activity:
  `N_CL_ModifyTreatment` (`= affectsCharge = true`) is corrected text but still not a guard.
  Nothing in these runs would fail if that condition were false.
* The engine is 8.10.0-alpha5 here. `DEF-14`'s measurement was made on 8.9.19, so the "a
  condition on a single outgoing flow is never evaluated" behaviour is not re-measured by this
  record on this version.

How to repeat it
----------------
Start the engine, copy `workers/.env.example` to `workers/.env`, then run the four commands above
from `workers/`. The engine-level tests deploy models and forms into the running engine and add
process instances to it; they are excluded from the default build for that reason.

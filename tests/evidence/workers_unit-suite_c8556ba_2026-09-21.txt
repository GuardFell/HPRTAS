UNUSABLE INPUT IS CONTROLLED, NOT FATAL
---------------------------------------
Every worker is called with input that is missing, mistyped or self-contradictory
and produces a BPMN business error carrying INVALID_VARIABLE, so the process can
take its modelled error path. Only a genuine defect fails the job (job.fail),
which is what the last two tests check, so an unexpected exception is retried by
the broker instead of leaving the job stalled.

Card and security details are refused with PROHIBITED_FINANCIAL_DATA and the
provider is not called - asserted, not assumed - on both the payment and the
refund path (AC-09).

DUPLICATES AND SECOND CHARGES
-----------------------------
The guards that AC-10 rests on all pass in this run: the same payment reference
is never charged twice, a declined attempt may be retried without a double
charge, retrying a booking after an outage creates no second appointment, and the
same payment is never refunded twice.

A MATTER OF RECORD, NOT A FAILURE
---------------------------------
The test names and the worker source comments cite the earlier, coarser
allocation of rule and requirement IDs, so a name such as "(TC-06, BR-04, AC-02)"
means BR-10 in the current list, and "(TC-04, BR-03)" means BR-07. This was
already true before this run; it is reported here because testing is where it
becomes visible. It is DEF-06 in ../test-plan.md, and the reconciliation table at
the top of ../../docs/requirements/requirements.md resolves each ID.

NOT COVERED HERE
----------------
- Anything needing the engine or a human: job activation and binding to the
  models (see the smoke and end-to-end evidence), the user tasks, the forms, the
  timers, the gateways and the boundary events. The unit tests call handlers
  directly and cannot reach those.
- Role-based access, task claiming and the audit trail (DEF-07), and a form
  filled in by a signed-in user (DEF-08).
- TC-02, TC-13, TC-16 and TC-20 have no worker-side behaviour to exercise.
- `npm run test:smoke` and `npm run test:e2e` were not run in this session: the
  engine (Camunda 8 Run) is not installed on the machine used, and
  `camunda-runtime/` is not part of the repository. Those two levels stand on the
  a7f0dd6 evidence. Both must be re-run before release 1.0.
- The suite was run on Node 24.21.0, outside the `>=20.12.0 <23` range the worker
  project declares; npm reported EBADENGINE. It passed, but the claim "tested on
  the declared engine" cannot be made (DEF-09).

# Documentation

Everything that describes the project rather than implements it.

| Path | Contents |
|---|---|
| `case-study-summary.md` | Shared understanding of the case: participants, process, business rules, exceptions, assumptions |
| `requirements/` | Functional and non-functional requirements and the traceability table |
| `deliverables.md` | What the group must produce, with owners, dates and acceptance criteria |
| `backlog/` | Product backlog, task breakdown, dependencies and sprint backlogs |
| `planning/` | Scope, estimation approach, task allocation, risks, timeline, planned vs actual |
| `agile/` | Definition of done and the contribution matrix |

Written in English. Keep the tables current as the project runs - they are the record of what
the group actually did, not a plan written at the end.

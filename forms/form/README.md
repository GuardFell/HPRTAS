# The forms, bundled by operational model

One folder per `core-N` model, holding a copy of every Camunda Form that model's user tasks bind. Generated by `ppt/bundle_forms_by_core.py` from the repository at **tag submission-2026-09-29** - the files in `forms/` beside this folder are the originals, and these are copies made for bundling and for a demonstration.

The same arrangement is documented, without the copies, in `forms/by-core.md` beside this folder.

## The forms that appear in more than one folder

5 of the 41 forms are bound by more than one model. They are copied into each model that binds them, because the variable contract is read by that model's tasks:

| Form | Bound in |
|---|---|
| `appointment-confirmation.form` | core-2, core-4 |
| `booking-request.form` | core-1, core-4 |

| `missing-information-request.form` | core-1, core-5 |
| `referral-check.form` | core-1, core-5 |

## Checking the bundle

```bash
python ppt/bundle_forms_by_core.py --check
```

It re-reads the five models, and reports any form that is missing from a folder, any extra file in one, and any copy that is not byte-identical to the original.

# Testing

| Path | Contents |
|---|---|
| `test-plan.md` | Scope, acceptance criteria (`AC-##`), test scenarios (`TC-##`), the execution record, defects and the simulated components |
| `evidence/` | Outputs, logs and screenshots from running the scenarios |

## Rules

- Acceptance criteria must be clear and measurable and linked to a requirement or business rule.
- Every piece of evidence identifies the **version under test** (a tag or commit).
- Failing results are recorded as plainly as passing ones, and unmet criteria are explained
  rather than removed.
- `evidence/README.md` gives the file naming convention.
